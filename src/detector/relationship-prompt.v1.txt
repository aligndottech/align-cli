CRITICAL INSTRUCTIONS FOR RELATIONSHIP DETECTION:
0. **AGREEMENT CHECK (do this BEFORE 1 or 2, on every SIMILAR DECISION pair)**: a decision stating a GENERAL rule ("when situation X happens, do Y") and a decision describing one CONCRETE instance of applying that SAME rule ("this case was situation X, so we did Y") are NOT incompatible - the second is an example of the first, not an opposing stance. This holds even when the concrete instance names specific details (a version number, a parameter value, a ticket) that the general rule states only abstractly, and even when the general rule was written AFTER the instance, extracted FROM it. Report "relates" or "supports" for this shape, never "incompatible". Only report "incompatible" when the two decisions could not BOTH be applied to the SAME concrete situation - never merely because one names a specific case and the other states the rule behind it.

1. **INCOMPATIBLE** - report type "incompatible" when the NEW DECISION and a SIMILAR DECISION take positions on the SAME subject that cannot both hold (e.g. "use X" vs "use Y" for the same job, a value set to 50 vs the same value capped at 25) - AFTER the agreement check above has ruled out the general-rule/concrete-instance shape. Merely restating the same topic is NOT an explicit reference.

2. **ARCHITECTURAL INCOMPATIBILITY**: report "incompatible" when two decisions propose approaches that CANNOT both be implemented simultaneously:

3. **REFINES vs CLARIFIES**:

Relationship types (SIMILAR DECISIONS):
- incompatible: The two decisions take positions on the same subject that cannot both hold - the conflict-vs-supersession verdict is computed outside this call from the Decided/By facts
- refines: ENHANCES or adds IMPLEMENTATION DETAILS to existing decision (specifications, technical details, concrete steps)
- clarifies: Adds detail without changing the core decision (explanations, context, rationale)
- duplicates: Essentially the same decision repeated
- relates: Related but not conflicting
- blocks: One decision PREVENTS progress on another (keywords: "cannot proceed until", "blocked by", "depends on")
- questions: One decision RAISES CONCERNS about another (keywords: "are we sure", "what about", "concern about")
- supports: One decision provides EVIDENCE for another (keywords: "this supports", "validates", "confirms")
